# Серце Підземелля (tower defense)

Tower defense у браузері в темі підземелля: гравець — володар підземелля, селить монстрів у ніші біля коридору,
авантюристи йдуть коридором до Серця. Запуск: відкрити `index.html` (сервер не потрібен).
Режими: кампанія (100 набігів) і безкінечний (рекорд у `localStorage`). Відладка: `index.html?wave=40&money=5000`.

## Стек
HTML5 Canvas + чистий JavaScript, без збірки і залежностей (шрифт Cinzel з Google Fonts, фолбек Georgia).
Скрипти — звичайні `<script>` (не ES-модулі), щоб працювало з `file://`. Порядок підключення важливий:
`config.js` → `entities.js` → `game.js` → `ui.js`. Усі мають спільну глобальну область видимості.

## Тема ↔ код
Код лишився з TD-назвами: `Tower` = монстр, `Enemy` = авантюрист, `money` = душі, `lives` = міцність Серця,
`wave` = набіг. Монстри: `archer` скелет-лучник, `cannon` вогняний імп, `frost` привид, `spider` павук,
`golem` голем, `lich` лич, `eye` око. Авантюристи: `normal` воїн, `fast` злодій, `tank` паладин, `gnome` гном,
`priest` жрець, `mage` маг, `scout` розвідник, `knight` вершник, `hero` герой-бос.

## Структура
- `js/config.js` — УВЕСЬ баланс: мапа/шлях, факели, `TOWERS`/`ENEMIES` (механіки описані коментарями над ними),
  рівні (`MAX_LEVEL`, `LVL_*`), набіги: `FIRST_WAVES` (1–10 вручну) + генератор `waveGroups(n)`
  (розклад появи `ENEMY_UNLOCK`, бос кожні 10, тематичний кожні 5), криві `hpMul(n)` / `rewardMul(n)`, `hash()`.
- `js/entities.js` — `towerStats(def, level)` (усі характеристики на рівні — і для гри, і для UI), `Enemy`
  (броня/щит/отрута/лікування/оглушення/невидимість через `hidden`/`revealed`), `Tower` (атаки `projectile`/`aura`/`beam`,
  детектори підсвічують невидимих), `Projectile` (сплеш, сповільнення, отрута, ланцюг `jump`),
  малювання: `drawAdventurer` (switch за типом), монстри через мапу `TOWER_DRAW`.
- `js/game.js` — стан `game` (`mode`, `over`: 'menu'|'win'|'lose', `auto`), `startWave`, `update(dt)`, рекорд;
  малювання: `buildMapLayer()` (кеш), факели, Серце, віньєтка, `drawEffect` (ефекти за `kind`: beam/bolt/quake/кола); цикл `frame`.
- `js/ui.js` — об'єкт `ui` (placing/selected/hover/tab), події миші й клавіатури, `refreshUI()` кожен кадр, `refreshOverlay()` (меню/кінець), старт гри.
  Розкладка: зліва панель набігу (`refreshRaid`) і бестіарій (`refreshBestiary`, за `game.seen` — хто вже з'являвся за цю гру);
  центр — canvas; справа вкладки «Монстри» / «Посилення» (`refreshUpgrade`, «зараз → після» через `towerStats()`).
  Іконки в панелях — маленькі canvas, що малюються тими ж функціями (`towerIcon`, `enemyIcon`).
- `style.css` — темний «кам'яний» інтерфейс, кольори в CSS-змінних `:root`.

## Правила
- Графіка — лише примітиви Canvas, без картинок.
- Відстані в config — у клітинках (`CELL` = 40px), швидкості ворогів — px/с.
- Новий монстр = запис у `TOWERS` + функція малювання в `TOWER_DRAW`; новий авантюрист = запис у `ENEMIES` + `case` у `drawAdventurer()`
  + (для генератора) `ENEMY_UNLOCK` і `WAVE_BASE`. Нова механіка монстра, що росте з рівнем, — у `towerStats()` і рядок у `refreshUpgrade`.
- Набіг відкриття нового типу — не кратний 5 (там тематичні/бос-набіги, новачок не потрапить першим).
- Склад набігів детермінований (`hash`), бо панель показує його наперед — не використовуй там `Math.random`.
- Статичне малюємо в `buildMapLayer()` (з `hash()`, щоб не мерехтіло); анімації — через глобальний `time`, не через ігровий `dt`.
- `refreshUI()` не перестворює DOM кожен кадр (лише textContent/класи), інакше ламаються кліки.
- Баланс перевіряли headless-прогоном у Node (заглушки DOM + бот): бот проходить кампанію з поодинокими проривами;
  край складності — `hpMul` з квадратичним коефіцієнтом ~0.0028 (зараз 0.0022).
