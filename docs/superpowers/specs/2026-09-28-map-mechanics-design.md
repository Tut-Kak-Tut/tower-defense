# Механіки мап: кілька шляхів і завали

Дата: 2026-09-28. Стосується лише рівнів (`?level=`); кампанія й безкінечний лишаються на стандартній мапі з одним шляхом.

## Мета

Урізноманітнити рівні двома механіками:
1. **Кілька шляхів** — рівень може мати кілька коридорів до Серця: окремі входи, що зливаються, або розвилка, що
   розходиться й сходиться знову. Загони набігу розподіляються між шляхами за вагами.
2. **Завали (каміння)** — клітинки поза коридором, де не можна селити монстрів. Мапа задає будівельний простір.

Плюс новий рівень на набіги 71–100 (зараз не покриті жодним рівнем), що показує обидві механіки.

Критерії успіху:
- усі наявні рівні працюють як раніше (переведені на новий API, мапи ті самі);
- на рівні з кількома шляхами загони йдуть різними коридорами, детерміновано, і гравець бачить наперед, хто куди піде;
- на завали не можна поселити монстра, вони видні на мапі й на мініатюрі головної;
- некоректна мапа падає в `build()` зрозумілою помилкою українською.

## Підхід

Кожен шлях — **повна ламана від входу до Серця** (спільні ділянки повторюються в кожній ламаній). Ворог пам'ятає
свій шлях (`route`), уся логіка руху (`wp`, `progress`, `setProgress`) працює з ним як зараз із єдиним шляхом.
Відкинуто: граф вузлів із розгалуженнями — ламає однозначність `progress` (ціль «перший», валун, телега), для мапи
20×12 зайвий.

## Опис рівня (`js/levels/level.js`)

`setMap(path, torches)` прибираємо, замість нього:

```js
new LevelBuilder('deep')
  …
  .addPath([[-1, 2], [8, 2], [8, 6], [20, 6]], 2)       // вага 2 (за замовчуванням 1)
  .addPath([[5, 12], [5, 8], [8, 8], [8, 6], [20, 6]])  // вхід знизу, зливається з першим
  .setRocks([[3, 4], [10, 0, 3, 2]])                    // клітинка [c, r] або прямокутник [c, r, w, h]
  .setTorches([[2, 1], …])
  .build();
```

Зберігається як `l.paths = [{ points, weight }]`, `l.rocks` — розгорнутий список клітинок `[c, r]`, `l.torches`.

Перевірки `build()` (повідомлення лише українською):
- хоча б один шлях; вага — додатне число;
- перша точка шляху — за краєм мапи: `col === -1` (зліва), `row === -1` (згори) або `row === ROWS` (знизу),
  при цьому інша координата в межах мапи;
- остання точка кожного шляху — `col === COLS`, і вона **однакова для всіх шляхів** (одне Серце);
- відрізки прямі; у межах одного шляху — без самоперетинів і без виходу за мапу (як зараз, клітинки за краєм на
  вході/виході не рахуються);
- різні шляхи можуть ділити клітинки (злиття/розвилка);
- жоден камінь і факел не в коридорі (будь-якого шляху); каміння — в межах мапи; каміння й факели не збігаються.

4 наявні рівні переписуємо: `setMap(path, torches)` → `.addPath(path).setTorches(torches)`. На 1–2 з них
додаємо трохи каміння для різноманіття (не чіпаючи ключових позицій біля коридору, щоб баланс не зсунувся).

## Рух (`js/entities.js`)

- `PATH_POINTS` → `ROUTE_POINTS` (масив ламаних: шляхи рівня або `[DEFAULT_PATH]`), `ROUTE_WEIGHTS`.
- `PATH_PX`/`PATH_LEN` → `ROUTES[i] = { px, len }` (довжини рахуються так само).
- `ROCKS` — клітинки завалів рівня (або `[]`).
- `Enemy` отримує `route` (індекс, за замовчуванням 0); `update` і `setProgress` беруть `ROUTES[this.route]`
  замість глобальних масивів. Початкова позиція — перша точка свого шляху (конструктор ставить 0, а `route`
  задається одразу після створення: або параметр конструктора, або `setRoute(i)`, що переставляє на старт).
- `spawnOnDeath()` (воїн вершника, половинки шута, вантаж телеги) — нові вороги успадковують `route` породжувача.
- Стрій (`leader`) не змінюється: увесь загін іде одним шляхом.
- Валун орка (`setProgress(progress − knock)`) працює по шляху самого ворога — без змін.

## Розподіл загонів

- `routeFor(n, squad)` (у `game.js` або `entities.js`): якщо шлях один — 0; інакше зважений вибір за
  `hash(n, squad)` серед `ROUTE_WEIGHTS`. Детерміновано, без `Math.random`.
- `startWave` кладе `route` у кожен елемент `spawnQueue` (номер загону `squad` уже рахується там), `update` при
  появі передає його в `Enemy`.
- `game.lastInSquad` лишається за номером загону — загін один, шлях один.

## Поселення й мапа (`js/game.js`)

- `PATH_CELLS` — об'єднання клітинок усіх шляхів. Новий `ROCK_CELLS`.
  `canPlace` відмовляє і для коридору, і для каміння. `bestDir` біхолдера рахує лише коридор (`PATH_CELLS`).
- `isPath` (малювання стін/підлоги) — лише коридор; каміння малюється окремо.
- `buildMapLayer()`: завали — нагромадження уламків скелі (кілька багатокутників різного відтінку, форма й
  поворот з `hash(c, r)`, щоб не мерехтіло), лише примітиви Canvas.
- Вхід (брама/темрява на вході) малюється для кожного шляху з урахуванням краю (лівий / верхній / нижній).
  Спільний вхід двох шляхів — одна брама. Серце — одне, в останній точці.
- Якщо шляхів більше одного — біля кожного входу буква A/B/C (стиль як у написів на мапі).

## UI

- Панель набігу (`refreshRaid`) групує за типом авантюриста, не за загоном. Якщо шляхів більше одного — у рядку
  типу мітка шляхів, якими цей тип іде в цьому набігу (напр. `A` або `A·B`); рахується з тих самих
  `routeFor(n, squad)`, що й у `startWave` (спільна функція розкладу набігу, щоб не розійтися).
- Мініатюра на головній (`home.js`): малює всі шляхи, каміння (сірі квадратики) і факели.

## Сейв

Без змін: шлях загону детермінований, набіг після завантаження починається спочатку. `SAVE_VERSION` не чіпаємо.

## Новий рівень «Глибини» (71–100)

- Набіги 71–100, усі монстри, два входи (зліва і згори/знизу) зі злиттям перед Серцем, вага головного 2, бічного 1,
  кілька завалів, що обмежують найвигідніші ніші.
- Стартові душі — оцінка доходу кампанії до 71-го набігу (порахувати зі `WAVES` нагороди + бонуси, як у коментарі
  `levels.js`), з округленням.
- Назва/опис двома мовами.

## Перевірка

- Відкрити кожен рівень і кампанію в браузері: без помилок у консолі, мапи ті самі, що до змін (крім доданого каміння).
- Навмисно зламати мапу (шлях з різним кінцем, камінь у коридорі) — `build()` кидає помилку.
- На «Глибинах» (`?level=deep&money=…`) переконатися: загони йдуть обома входами згідно з мітками панелі, стрій
  тримається, телега/шут/вершник породжують на своєму шляху, валун відкидає по своєму шляху, на камінь не поселити.
- Баланс «Глибин» — ручною грою (бота в репозиторії немає; відновлення бота — окрема задача за бажанням).
